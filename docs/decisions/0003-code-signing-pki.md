# 0003：程式碼簽章與跨企業憑證信任

- 日期：2026-09-27（同日補充「裝置控制與驅動簽章」「防毒設定」）
- 狀態：建議中（待確認公司 AD / CA 架構與防毒產品）
- 相關：[PRD](../PRD.md) 5.2–5.3（硬體 / 網路控管）、第 7 節（腳本與安裝檔需簽章）、第 8 節風險與待決事項、[0001](0001-nginx-gateway-and-grpc.md)（Agent mTLS）、[0002](0002-software-deployment.md)（派送時驗證簽章）

## 結論

1. RustIt 的 Agent、使用者端程式、安裝檔（MSI）與 IT 下發的 PowerShell 腳本一律簽章。
2. 程式只在公司網域電腦使用，**先用公司自己的 AD 憑證服務（AD CS）簽發程式碼簽章憑證**，不另外購買。需要給網域外的電腦使用時，再購買公開憑證。
3. 子企業電腦只接收「信任」（根憑證與簽章憑證的公開部分），**簽章用的私密金鑰只留在母公司負責簽章的人手上**。
4. 子企業若在不同樹系，要另外發布母公司根憑證，並提供可跨網路存取的 HTTP 憑證撤銷清單（CRL）位址。
5. USB、Wi-Fi 的偵測與基本控管**全部在一般程式層（使用者模式）實作，不開發核心驅動**，因此公司 AD CS 的憑證就足夠。需要核心驅動時，必須改用 EV 憑證並經微軟簽署。
6. 不論是否簽章，**防毒 / EDR 都要另外設定允許規則**；簽章讓允許規則可以依「發行者」設定，不必每次改版更新。

## 取得憑證的三種方式

| 方式 | 適合 | 費用 | 誰會信任 |
| --- | --- | --- | --- |
| **A. 公司 AD CS 自己簽發（採用）** | 只在公司內部、已加入網域的電腦使用 | 免費（公司已有 AD CS 時） | 網域內的電腦（本來就信任公司的根憑證） |
| B. 向公開憑證機構購買（OV 程式碼簽章） | 要給網域外的電腦、廠商或客戶使用 | 約 US$200–500／年 | 全世界的 Windows |
| C. Azure Trusted Signing（微軟雲端簽章服務） | 不想自行保管實體金鑰 | 約 US$10／月 | 全世界的 Windows；開放申請的國家有限，台灣公司是否可申請需確認 |

採用 A 的理由：使用範圍只在公司網域內、免費、由 GPO 集中管理信任；安裝與派送都透過 Agent，不經瀏覽器下載，不會觸發 SmartScreen 的下載信譽檢查。

## 方式 A：公司 AD CS（由管理 AD 的 IT 操作）

1. **建立範本**：在 CA 伺服器開「憑證範本」主控台，複製內建的「程式碼簽章」範本，只開放負責簽章的 AD 群組（例如 `RustIt-Signers`）申請，然後發布範本。
2. **申請憑證**：簽章人員在自己的電腦開 `certmgr.msc` →「個人」→「要求新憑證」，選擇該範本。私密金鑰設為不可匯出，或存放在硬體金鑰中。
3. **發布「受信任的發行者」**：把這張憑證（公開部分）加入 GPO「電腦設定 → 原則 → Windows 設定 → 安全性設定 → 公開金鑰原則 → 受信任的發行者」。之後 PowerShell 執行原則、AppLocker / WDAC 都可以用「發行者」規則，只允許 RustIt 簽過的程式執行。

## 方式 B：向公開憑證機構購買（備案）

- **在哪買**：台灣可找 TWCA（台灣網路認證）；國際常見的有 DigiCert、Sectigo、GlobalSign、SSL.com。
- **要準備的文件**：
  - 公司登記資料（統一編號、經濟部商工登記）；
  - 可查到的公司電話（憑證機構會來電確認），部分機構要求鄧白氏（D-U-N-S）編號；
  - 申請人的在職證明。
- **審核時間**：約 3 天到 2 週。
- **金鑰必須存在硬體中**：2023 年起的業界規定，私密金鑰必須存在 USB 硬體金鑰、HSM 或憑證機構的雲端簽章服務，不能再只下載 `.pfx` 檔案。
- **SmartScreen**：從網路下載的檔案依「信譽」決定是否警告，新憑證初期仍可能跳警告，隨下載執行次數累積後才消失。微軟已取消 EV 憑證可立即略過警告的優待，實際政策以申請時為準。

## 簽章與驗證

簽章工具 `signtool.exe` 隨 Windows SDK 安裝（開發機位置：`C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe`）。

```bash
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /sha1 <憑證指紋> dist/RustIt-Demo.exe
```

- `/sha1`：指定使用哪一張憑證，指紋可在 `certmgr.msc` 的憑證詳細資料中找到。
- `/tr`：時間戳記伺服器，**一定要加**。有時間戳記，憑證過期後先前簽過的檔案仍然有效。

驗證：

```bash
signtool verify /pa /v dist/RustIt-Demo.exe
```

或在檔案上按右鍵 →「內容」→「數位簽章」分頁。

**建置流程**：編譯後自動執行 `signtool`；之後以 Tauri 打包安裝檔時，可在 `tauri.conf.json` 的 `bundle.windows` 設定憑證指紋、雜湊演算法與時間戳記伺服器，由打包流程自動簽章。

## 子企業：跨網域 / 跨樹系的憑證信任

AD 的信任關係只處理帳號驗證與授權，**不會自動讓對方信任你的憑證**。是否需要額外設定，取決於子企業與母公司是否在同一個樹系。

| 架構 | 例子 | 母公司 CA 根憑證 | 要做的事 |
| --- | --- | --- | --- |
| **同一個樹系**（子企業是子網域） | `corp.local` 底下的 `sub.corp.local` | **自動信任**：企業 CA 發布在整個樹系共用的設定區，所有網域電腦自動信任 | 只需在各網域的 GPO 加上「受信任的發行者」（GPO 依網域分開，每個網域各做一次） |
| **不同樹系，建立信任** | `corp.local` ↔ `subsidiary.local` | **不會自動信任** | 1. 把母公司根憑證（與中繼 CA 憑證）發布到子企業 AD；2. 子企業 GPO 加上「受信任的發行者」；3. 確認子企業電腦連得到母公司的 CRL（見下節） |

不同樹系時，由子企業的樹系管理員（Enterprise Admins）執行，把母公司根憑證發布給整個子企業樹系：

```bash
certutil -dspublish -f ParentRootCA.cer RootCA
```

也可以改用子企業的 GPO 匯入：「電腦設定 → 原則 → Windows 設定 → 安全性設定 → 公開金鑰原則 → 受信任的根憑證授權單位」。

### 注意：憑證撤銷清單（CRL）要能跨網路存取

- **問題**：企業 CA 預設把 CRL 發佈點與授權資訊存取（AIA）設為 **LDAP** 路徑（`ldap:///CN=...`），指向母公司自己的 AD；其他樹系的電腦通常查不到。
- **後果**：簽章狀態可能顯示「無法檢查撤銷狀態」；RustIt Agent 驗證安裝檔、腳本簽章時可能失敗（[0002](0002-software-deployment.md)、PRD 第 7 節都依賴這項驗證）。
- **對策**：在 CA 加上 **HTTP** 發佈點（例如 `http://pki.corp.com/cdp/...`），並確認子企業網路可存取。發佈點寫在憑證裡，加上後要重新簽發才生效，**應在申請程式碼簽章憑證之前完成**。

在子企業的電腦上檢查每個撤銷檢查網址能否連上：

```bash
certutil -verify -urlfetch CodeSigning.cer
```

### 如何判斷是哪一種架構

請管理 AD 的同事打開「Active Directory 網域及信任」，查看信任類型：

- 「父子」或「樹狀根目錄」→ 同一個樹系。
- 「樹系」或「外部」→ 不同樹系。

### 與 Agent mTLS 憑證的關係

相同原則也適用於 Agent 的 mTLS 裝置憑證（[0001](0001-nginx-gateway-and-grpc.md)）：母公司 CA 發給子企業電腦的憑證，同樣需要根憑證信任與可存取的 CRL。若要讓子企業電腦**自動註冊**母公司 CA 的憑證，跨樹系的設定更複雜，另行規劃。

## 裝置控制與驅動簽章

偵測 USB、Wi-Fi 裝置不需要寫驅動，Windows 在一般程式層（使用者模式）就提供足夠的 API；只有深度資料外洩防護（DLP）類功能才需要核心驅動，而這些已列為 PRD 第一版的非目標。

| 功能 | 不寫驅動的做法 | 需要驅動嗎 |
| --- | --- | --- |
| 偵測 USB 插拔、列出裝置與序號 | 裝置變更事件（`WM_DEVICECHANGE` / `CM_Register_Notification`）、WMI `Win32_PnPEntity`、SetupAPI | 不需要 |
| USB 儲存裝置封鎖 / 唯讀 | Windows 內建「卸除式存放裝置存取」原則（可設禁止寫入）、登錄檔 `USBSTOR` | 不需要 |
| USB 白名單（只允許特定序號） | Windows 內建「裝置安裝限制」原則，依裝置執行個體 ID 允許或阻擋（Windows 10 2004 起支援分層規則） | 不需要 |
| 停用藍牙、光碟機等特定裝置 | `pnputil /disable-device` 或 `CM_Disable_DevNode` | 不需要 |
| 偵測 Wi-Fi（網卡、目前 SSID、附近網路） | WLAN API（`WlanEnumInterfaces`、`WlanRegisterNotification` 等） | 不需要；Windows 11 24H2 起讀取 SSID 可能需要「位置」權限，Agent 以服務執行時的行為需實測 |
| 限制只能連公司 Wi-Fi | WLAN API 的 SSID 過濾清單（等同 `netsh wlan add filter`） | 不需要 |
| 網站封鎖、程式連線限制 | WFP 使用者模式 API（`FwpmFilterAdd0`，由 BFE 服務執行） | 不需要 |
| **記錄複製到 USB 的檔案名稱與內容** | — | **需要**（檔案系統 minifilter 驅動） |
| **檢查加密流量內容、網址細部過濾** | — | **需要**（WFP callout 驅動） |

若公司已有 Microsoft Defender for Endpoint 授權，其內建「裝置控制」可依序號控管 USB、設唯讀並記錄存取，也不必自行開發驅動。

### 若日後需要核心驅動

| 項目 | 說明 |
| --- | --- |
| 憑證 | 公司 AD CS 的憑證**不能**用於驅動。需向公開憑證機構購買 **EV 程式碼簽章憑證**（約 US$300–700／年），用來註冊微軟 Partner Center 的硬體開發帳號。 |
| 微軟簽署 | 驅動上傳 Partner Center，由微軟簽章後才能發佈。Windows 10/11 可用「證明簽署」；**Windows Server 必須通過 HLK 完整測試**（PRD 目標含 Server 2016 以上）。 |
| 相容性 | 新版 Windows 11 預設開啟「記憶體完整性」（HVCI），驅動必須相容；並須避開微軟的易受攻擊驅動封鎖清單。 |
| 測試 | 只有開發機可開「測試簽章模式」（`bcdedit /set testsigning on`）載入未經微軟簽署的驅動，正式環境不可使用。 |
| 風險 | 驅動錯誤會造成藍屏並影響全公司，開發與測試成本遠高於使用者模式程式。 |

## 防毒 / EDR 設定

RustIt Agent 的行為與監控軟體或遠端控制木馬相似：以 SYSTEM 常駐、下載並安裝程式、執行 PowerShell、封鎖 USB、修改網路規則、安裝 RustDesk，容易被防毒或 EDR 攔截。

**簽章的作用**：允許規則可以依「發行者憑證」設定，一次涵蓋所有 RustIt 程式與後續版本。**簽章不代表防毒自動放行**，公司自簽憑證在微軟雲端也沒有信譽。

**Microsoft Defender**（以 GPO / Intune 或 Defender 管理主控台設定）：

1. **依憑證允許**：在 Defender for Endpoint「指標」新增憑證類型的允許規則，比排除路徑安全。
2. **攻擊面縮小（ASR）規則**：例如「封鎖透過 PSExec 和 WMI 建立的程序」可能阻擋 Agent，需將 Agent 加入對應規則的排除清單。
3. **不修改 Defender 設定**：Agent 不得嘗試變更 Defender 設定；「竄改防護」會阻擋，且此行為會被判定為惡意。

**第三方防毒**（趨勢 Apex One、Symantec、卡巴斯基等）：在各自的管理主控台將 RustIt 加入信任程式 / 核准清單，依憑證或雜湊值設定。

**RustDesk**：多數防毒會將其標示為「遠端管理工具」類的可能不需要的程式（PUA），需一併加入允許清單。

**降低誤判的其他做法**：

- **分批上線**：先在 IT 部門試跑，確認未被攔截再擴大（PRD 第 8 節已規劃分批發布）。
- **提交誤判申訴**：被 Defender 誤判時，可到微軟 Security Intelligence 網站以軟體開發者身分提交檔案，申請重新判定。

## 待確認

- [ ] 公司使用的防毒 / EDR 產品與管理方式（Defender for Endpoint、趨勢、Symantec…），由誰設定允許規則。
- [ ] 公司是否有 Microsoft Defender for Endpoint 授權（可直接使用其 USB 裝置控制）。
- [ ] 是否有需要核心驅動的需求（例如記錄複製到 USB 的檔案）；若有，是否願意購買 EV 憑證並走微軟簽署流程。
- [ ] Windows 11 24H2 以上，Agent 以服務身分讀取 Wi-Fi SSID 是否受「位置」權限限制（需實測）。
- [ ] 公司是否已架設 AD CS？是單層（企業根 CA）還是兩層（離線根 CA + 發行 CA）？
- [ ] 各子企業與母公司是同一個樹系，還是不同樹系的信任關係？
- [ ] CA 目前的 CRL / AIA 發佈點是否有 HTTP 路徑，子企業網路能否存取？
- [ ] 負責簽章的人員與保管方式（誰可以簽、私密金鑰放在哪裡）。
- [ ] 子企業是否需要自行簽章自己的程式（需另外核發憑證或使用自己的 CA）。
- [ ] 是否有網域外的電腦需要使用 RustIt（決定是否需要購買公開憑證）。
